## 0. 基本方針

段階Bのバックテストは、**実際に運用してきた入力のまま**現行ロジックを過去のレースに当てる。
運用で埋めてこなかった項目を新たに埋める拡張は、段階Bの結論が出た後に別アドendumで扱う。

## 2. Q1 rank の変換表について

| 項目 | 内容 |
|:--|:--|
| 作り方 | SmartRc 実データの（推人, 人ラ）の組から、推定人気 → rank の固定変換表を作る |
| 作成条件 | （推人, 人ラ）の組が **30組以上**たまってから作る |
| 記録用キー | 任意キー `rank_source` を追加する方針。値の例: `"smartrc"`（SmartRc の人ラをそのまま入力）／ `"map_v0"`（暫定変換表）／ `"map_v1"`（変換表 v1 で作成）。**判定には使わない** |
| 暫定 | 30組たまるまでは暫定変換表 **map_v0**（§2.1）を使う（2026-10-12 決定） |

コード上の事実として、rank が欠けた馬は `"C"` として扱われ、評価点 +8 が付く（16キー定義メモ §4-3）。

### 2.1 暫定変換表 map_v0（2026-10-12 決定）

| 推定人気（est_pop の代替値） | rank |
|:--|:--|
| 1 | A |
| 2 | B |
| 3〜5 | C |
| 6〜10 | D |
| 11以上 | E |

| 項目 | 内容 |
|:--|:--|
| 材料 | SmartRc 実データの（推人, 人ラ）の組 27組 |
| 2026-09-20 オールカマー | 13組。全組が map_v0 と一致 |
| 2026-10-12 スワンS | 14組。不一致3組（推1→B、推5→D、推11→D） |
| 一致率 | 24/27 ≈ 89% |
| 記録 | export する各馬に `rank_source: "map_v0"` を記録する |
| 次の版 | （推人, 人ラ）が30組以上たまったら map_v1 を作る |
| 禁止事項 | 検証期間（2024〜2025）の結果を見てから表を変えない（アドendum §7 の過学習禁止と同じ） |

### 2.2 全頭 C 扱いを採らない理由

- `judgeConfidence` は、軸信頼度「高」の条件に「スコア1位の rank が A か B」を含む（index.html 1579 行）。
- 全頭を C にすると軸信頼度「高」が一度も出なくなり、🎯買い場・💰堅め単発の判定も出なくなる。現行運用と判定の性質が変わるため採らない。
