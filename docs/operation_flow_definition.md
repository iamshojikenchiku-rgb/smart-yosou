# Smart予想ツール 週次運用フロー定義書

最終更新: 2026-06-21
目的: 新チャットでもClaudeがこの1枚で同じ運用に即入れるようにする。

---

## 0. 前提・現状

- ツール本体: GitHub Pages公開・**自己完結版**（React/ReactDOM/変換済みコードをインライン化、unpkg依存ゼロ）。
  URL: `https://iamshojikenchiku-rgb.github.io/smart-yosou/`（"smart-yosou"は半角）。
  **正本はGitHubにアップロード済みの実ファイル**。新チャットのClaudeは必要時にraw取得で現状把握する。
- 血統エンジン: A〜F層。SmartRc小系統に整合済み。
  - A:父系×条件 / B:母系補正(母父+母母父) / C:産駒世代 / D:騎手相性 / E:母実績 / **F:種牡馬個別（買い・消し）**
  - 新内部タイプ: `france_eu`（エピファネイア系等＝良馬場◎・非根幹◎・道悪軽微耐性）、`sunday_dirt`（Dサンデー系）。
- フェーズ: データ蓄積期（〜2027年5月目安）。SmartRc併用。最終目標は完全オリジナル化。

## 1. 週次運用フロー（7ステップ）

| # | 担当 | 内容 |
|:--|:--|:--|
| 1 | ユーザー | Perplexityの情報をClaudeに渡す |
| 2 | **Claude** | 情報を分析し**購入レースを決定**（日程は必ず検索で確認） |
| 3 | ユーザー | 決定レースの出馬表・血統データをスクショ |
| 4 | **Claude** | スクショから**全頭JSONを作成** |
| 5 | ユーザー | ツール判定に従い購入 |
| 6 | ユーザー | レース後に結果をスクショ |
| 7 | **Claude** | 結果分析→**F層追加・サンプル記録・収支更新・文書化**を自動実行 |

- **ステップ2・7はユーザー確認を取らず自動で進める**（時間節約のため）。
- ステップ2・4・7がClaude担当。

---

## 2. 各ステップの判断基準・ルール

### ステップ2：購入レース決定
- 日程・開催・レース名は**必ずSearchで確認**（Claudeは競馬日程のハルシネーション歴あり。推測禁止）。
- 優先候補：荒れやすい条件（ツールのARERU_RACES、混戦・ローカル・小回り・道悪含み）かつ妙味が出やすいレース。
- 月予算10,000円のペース配分を踏まえ、原則1〜2レースに絞る。
- 別基準の指定があればそれを優先。

### ステップ4：JSON作成
- **全頭入力を厳守**（下位人気馬も。穴馬取りこぼし防止＝過去の失敗パターン）。
- スキーマ：15キー＋任意`chichi_mei`＝最大16キー。
  `uno, name, est_pop, rank, odds, pop_tan, rider_change, cond_change, bonpaso, chichi_kei, chichi_mei(任意), haha_chichi_kei, hahahaa_kei, kishu_mei, haha_seiseki, sanka_sedai`
  ＋レース単位で`courseType`（"big_turf"/"dirt"等7カテゴリ）。
- `chichi_kei`はSmartRc表示の小系統そのまま（例: Tサンデー系, ロベルト系）。
- 種牡馬名が分かる馬は`chichi_mei`も入れてF層を効かせる（例: "モズアスコット"）。
- `est_pop`（推定人気）はSmartRcの値を使用。

### ステップ5：購入（ツール判定は絶対）
- 🛑/🚫/⚠️が出たら理由を問わず見送り。
- 予算ティア：勝負所3,000円／買い場1,500円／通常500円／見送り0円。
- 勝負所発動＝スコア差≥20 ∧ 荒れスコア≥65 ∧ 過大評価馬警告 の3条件同時成立。
- メイン=ワイド、サブ=3連単少額。1票100円（点数×100円）。

### ステップ7：結果分析・蓄積（自動）
- 結果スクショが正本。**確定着順・確定馬場は推測しない**（検索だと前年結果に化ける危険）。
- やること：買い目の的中/不的中判定 → ねじれサンプル等の記録 → 連対馬の種牡馬をF層へ追加（検証付き）→ 収支更新 → アドendum文書化。
- コード変更は必ず検証：構文チェック＋jsdom実描画で「開く」ことを確認してから納品。

---

## 3. Claudeが自力取得できないもの（ユーザー入力が必要）

- **SmartRcの推定人気**（事前予想に必須）→ ステップ1・3で受領。
- **確定着順・確定馬場**（結果照合に必要）→ ステップ6のスクショで受領。

この2点以外（分析・レース選定・JSON作成・買い目算出・F層追加・文書化・収支記録）はClaudeが自動で行う。

## 5. 不変の運用ルール（再掲）

- ツール判定は絶対。全頭JSON必須。日程は必ず検索確認。
- マクロ判定（荒れスコア・妙味）とミクロ判定（個別馬スコア）を独立追跡。
- 設計変更はアドendum方式で根拠とともに文書化。
- コード変更はJSX相当の編集→構文チェック→jsdom描画確認→納品。
- F層は「実際に扱ったレースの連対種牡馬」から優先的に育てる（174頭一括転記はしない）。
