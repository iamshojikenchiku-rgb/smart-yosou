# Smart予想システム 運用マニュアル v1.0

- 対象: Smart予想ツール（index.html）＋ 定時ジョブ J1/J2/J3 ＋ GitHub（smart-yosou）＋ Claude プロジェクト「AI予想」
- 読者: 運用する本人（タブレット・スマホ中心、PC は必要時）
- 関連: ツール画面の操作は `docs/USER_MANUAL.md`、ジョブの中身は `docs/jobs/`、ルールは `CLAUDE.md`・運用フロー定義書
- 作成日: 2026-09-13

## 0. このマニュアルの位置づけ

ツールの「画面の使い方」は `docs/USER_MANUAL.md` に書いてあります。本書は、その周りにある**仕組み全体を毎週どう回すか**をまとめたものです。木曜夜から翌週月曜までの1サイクルを、自分が何を・どこで・いつやるかの順に追えるように書いています。§7 のトラブル対応は、2026年9月の立ち上げ時に実際に起きたことをそのまま載せています。

## 3. 各ステップの操作

### 3.1 木曜夜：候補の承認
1. 通知（プッシュ／メール）から Claude アプリを開き、プロジェクト「AI予想」→ ドキュメント → `claude/weekly/YYYY-MM-DD_候補.md` を読む。
2. 見るところは4つ。候補レースと日付、選定理由（ARERU_RACES 該当／ハンデ／小回り／混戦）、**出典URL**（無ければ信用しない）、「要確認」と書かれた項目（例: ハンデ戦かどうか）。
3. 承認・差替は、**チャットで一言**（「チャレンジCで進める」「ラジオ日本賞に差替」）か、**メモ末尾に「更新」節を追記**のどちらでも可。J2 はメモを読むので、差替はメモに残しておくのが確実。
4. 予算メモ（今月残額・今週上限）も同じメモに出ています。残額が少ない週は候補が減ります。

### 3.2 金曜夜まで：スクショの投入
1. SmartRc で承認レースの画面を開き、**出馬表・血統（父小系統／母父／母母父／種牡馬名）・推定人気・複勝オッズ**をそれぞれスクショ。全頭が入るまで複数枚に分ける。
2. ファイル名を規約どおりに変更する（タブレットの「Files」アプリ等で名前の変更）。
   - 規約: `YYYYMMDD_<レース名>_<種別>_<連番>.png`
   - 種別: `出馬表` / `血統` / `推定人気` / `オッズ`
   - 例: `20260919_チャレンジC_出馬表_1.png`、`20260919_チャレンジC_推定人気_1.png`
3. Claude アプリでプロジェクト「AI予想」を開き、**ファイルを追加**（プロジェクトの知識／ファイル欄の「＋」）から選んで投入。
4. J2 は「対象日の `YYYYMMDD_` で始まる png」だけを読みます。日付を間違えると読まれません。書籍ページ（211〜386.png 等）は日付で始まらないので混ざりません。

### 3.3 土日朝：買い目メモの読み方と購入
1. `claude/weekly/YYYY-MM-DD_買い目.md` を開く。**冒頭の「結論」**が「購入可」か「見送り（理由）」か「予算超過のため見送り」かを最初に見る。
2. 見送りの日は買い目欄が「参考表示・購入しない」になっています。**理由を問わず買わない**（🛑／🚫／⚠️）。
3. 購入可の日は「買い目」欄の券種・馬番・点数・金額をそのまま買う。合計は週上限 2,500 円（勝負所のみ 3,000 円）以内に judge.js が収めています。
4. 判定を自分の目で確かめたいときは、メモ末尾の「入力JSON」をコピーし、ツールの **取込** に貼って **読み込む →**。同じ結果が出ます（差があれば §7 へ）。
5. 当日の最終オッズで妙味が消えていれば減額・見送りは可。増額・馬番の追加はしない。
6. 「未読取・要確認」欄に馬番が挙がっていたら、その馬の推定人気などをスクショで確認し、必要なら手入力で補って再判定する。

### 3.4 レース後：結果記録
1. 結果画面（着順・払戻）をスクショし、`YYYYMMDD_<レース名>_結果_1.png` の名前でプロジェクトに投入。
2. チャットで「結果記録。購入 ○○円・払戻 ○○円」と伝える（見送った週は「見送り・購入0円」）。
3. Claude（J3）が着順・確定馬場・払戻を読み取り、`data/samples/` にサンプル、`data/ledger.json` に台帳行を追加し、`npm run backtest` を実行して `claude/weekly/YYYY-MM-DD_結果.md` に要約を書きます。
4. J3 は「連対馬の種牡馬で SIRE_PROFILES に無いもの」を**追加案**として書きますが、実装はしません（§6 のバージョンアップ手順で反映）。
5. ツール側でも同じ結果を入れておくと統計画面に反映されます（USER_MANUAL §6.2）。任意。

### 3.5 月初：収支とバックテストの確認
- 結果メモ末尾の「今月の収支」（`node scripts/ledger.js summary` の出力）で、購入・払戻・回収率・残額を確認。
- バックテストは **10レース未満は結論を出さない**規律です。G層πを買い目に使うかの判断は、10レース以上・π候補の複勝回収率100%超・該当15件以上が揃ってから、別アドendumで行います。

## 4. 定時ジョブの管理

| したいこと | 操作 |
|:--|:--|
| 通知が来たか確認 | プッシュ通知／メール。届かない週は Claude アプリのスケジュールタスク一覧で「最終実行」を見る |
| 今すぐ動かしたい | スケジュールタスク一覧から該当ジョブを手動実行（「今すぐ実行」）。または新しいタスクで「J2 の手順で今日の判定を」と依頼 |
| 一時停止／再開 | 同じ一覧で該当ジョブをオフ／オン（旅行や休止週） |
| 時刻を変える | 同じ一覧で編集。時刻は JST 表示。変えたら `docs/jobs/README.md` の表も合わせる |
| 結果記録（J3） | 定時登録なし。§3.4 のとおりチャットで依頼 |

ジョブは毎回「新しいセッション」で動き、会話の記憶を持ちません。必要な文脈は `docs/jobs/` の手順書とプロジェクト知識から読む前提なので、**ルールを変えたいときは手順書を直す**のが正しい方法です（チャットで一度伝えても次回には残りません）。

## 5. GitHub の基本操作（タブレット／スマホ）

前提: Chrome で `https://github.com/iamshojikenchiku-rgb/smart-yosou`。操作するときは Chrome メニュー ︙ → **PC版サイト** にチェック。**自動翻訳は切る**（︙ → 翻訳 → 「英語」、右端 ︙ → 「このサイトは翻訳しない」）。翻訳中はファイル名まで日本語に見え、編集で事故になります。

| したいこと | 操作 |
|:--|:--|
| 公開状態の確認 | リポジトリ名の横が **Public** なら公開中。Private だと Pages が止まりツールが 404 になる |
| Public に戻す | Settings → General 最下部 Danger Zone → Change visibility → Make public → リポジトリ名を入力 → 確定。続けて Settings → Pages で Branch: main / (root) を確認 |
| ファイルを見る | フォルダをタップ → ファイル名をタップ |
| ファイルを追加・上書き | **入れたいフォルダを先に開いてから** Add file → Upload files → choose your files。スマホはフォルダ階層が付かないので、フォルダごとに分けて上げる |
| ファイルを別フォルダへ移動 | ファイルを開く → 鉛筆（Edit）→ 一番上のファイル名欄の先頭に `docs/` のようにフォルダ名を**1回だけ**入力 → Commit changes… → Commit changes |
| ファイルを削除 | ファイルを開く → 「…」→ Delete file → Commit changes |
| PR をマージ | 上部タブ Pull requests → 対象 PR → 「Merge pull request」→「Confirm merge」。終わったら「Delete branch」で作業ブランチを消してよい |
| 障害かどうか | エラー画面（500 など）が出たら `https://www.githubstatus.com/` を確認。赤や黄があれば時間を置く |

コミットメッセージは短くて構いません（例「docs: マニュアル追加」）。ブランチは常に **main** に直接コミットして問題ないのは文書だけです。**index.html と scripts は必ず PR 経由**（§6）。

## 6. Claude への依頼の型

### 6.1 普段の依頼（このプロジェクトのチャットで）
- レースの分析・JSON作成: 「このスクショで全頭JSONを作って judge.js で判定して」
- 結果記録: 「結果記録。購入○円・払戻○円」（§3.4）
- 質問: 「今月の残額は」「先週の判定の根拠は」

チャットの Claude はプロジェクト知識の索引 `docs/00_INDEX.md` を最初に読む約束になっています。

### 6.2 バージョンアップ（コード変更）の依頼
1. **先にアドendumを書く**（または書かせる）。`docs/design_addendum_g_layer_pi_v0.1.md` が雛形。目的・変更範囲・変更禁止事項・検証方法を含める。
2. **リポジトリを選んだタスク**を起こす。Chrome で `https://claude.ai/code?repositories=iamshojikenchiku-rgb/smart-yosou` を開くと、smart-yosou が選択済みで始まる（リポジトリを選ばずに始めると push できず 403 になる）。
3. 依頼文の型:
   「`docs/<アドendum>` の範囲のみを実装。CLAUDE.md の禁止事項を厳守。`feature/<名前>` ブランチで1モジュール1コミット。`npm run check` が通ってから次へ。PR を作成し、main へのマージは私が確認してから。」
4. PR の差分と実装メモ（Claude が `docs/implementation_notes_*` に書く）を読み、GitHub で **Merge**（§5）。
5. 公開URLとタブレットで表示確認。おかしければ PR を Revert（PR ページの「Revert」ボタン）。

Claude が「設計書に無いので実装せず提案に留めました」と言ってきたら、それは正しい動作です。採用するならアドendumに追記してから次のタスクで依頼します。

## 7. トラブル対応（立ち上げ時に実際に起きたもの）

| 症状 | 原因 | 対処 |
|:--|:--|:--|
| ホーム画面のアイコンから開けない／404 | リポジトリを Private にした（セキュリティ設定変更時など）。無料プランでは Pages が止まる | §5 の「Public に戻す」。Pages の再有効化も確認。ツールは静的ファイルで秘密情報は無く、公開して問題ない。収支と設計書を公開したくなければ index.html だけの別リポジトリに分ける |
| GitHub の画面が日本語になり、フォルダ名が「データ／ドキュメント」、ファイル名が「ユーザーマニュアル.md」 | Chrome の自動翻訳 | ︙ → 翻訳 → 英語。「このサイトは翻訳しない」に設定 |
| ファイル移動で「malformed path component」 | ファイル名欄の先頭に `/` が重複（`docs//USER_MANUAL.md`） | 欄の先頭の `/` を Backspace で1つ消す。`docs/` は1回だけ |
| 「Ooops!!! 500」でコミットできない | GitHub 側の障害 | githubstatus.com を確認し、時間を置いて再実行 |
| Cowork から push が 403 | タスク作成時にリポジトリを選んでいない | §6.2 のとおりリポジトリを選んだ新しいタスクで行う。既存タスクに後付けはできない |
| アップロードしたファイルがルートに入った | スマホのファイル選択はフォルダ階層が付かない | 入れたいフォルダを先に開いてからアップロード。入ってしまったら §5 の「移動」 |
| 日本語ファイル名が化けた（`繧ｷ繧ｹ繝…`） | Web アップロード時の文字コード | 設計書はASCII名（`system_architecture_…` 等）で置く。化けたファイルは中身を確認して削除 |
| J2 が「入力待ち」で終わった | 対象日の `YYYYMMDD_` で始まる png が無い | ファイル名の日付と種別を確認して投入し、手動実行するか、翌日の J2 を待つ |
| J1/J2 が「未マージのため実行できません」 | main に `scripts/judge.js` が無い | PR をマージして main を最新にする |
| メモの判定とツールの判定が違う | 入力JSONの貼り間違い、または index.html の版が違う | メモ末尾のJSONを丸ごと貼り直す。ツールを再読み込み（キャッシュ更新） |
| 保存済みレースが消えた | ブラウザのサイトデータ削除・別ブラウザ | 端末内保存のため復元不可。大事なものは「JSONをコピー」で外に出す |

## 8. 守ること（鉄則）と変えないもの

- ツール判定は絶対。🛑／🚫／⚠️ は理由を問わず見送り。
- 買い目は `scripts/judge.js`（＝ツール）の出力以外から作らない。Claude の所見は「所見」欄に分ける。
- 全頭入力。推定人気は SmartRc の値。確定着順・馬場・払戻は結果スクショから。
- 日程・レース名・出走表は検索で確認し出典URLを残す。出典の無い候補は採用しない。
- 月予算 10,000 円・週 2,500 円（勝負所 3,000 円）・原則1〜2レース。
- 荒れスコア・軸信頼度・閾値・予算ティア・買い目ロジック・16キースキーマ・単一ファイル構造は変更しない。変えるならアドendum → PR → 人がマージ。
- G層πは表示のみ。基準達成（10レース・回収率100%超・15件）まで買い目に使わない。

## 9. 用語

| 用語 | 意味 |
|:--|:--|
| J1／J2／J3 | 候補選定（木）／判定・買い目（土日）／結果記録（合図）の各ジョブ |
| 候補メモ／買い目メモ／結果メモ | プロジェクト知識 `claude/weekly/` の週次成果物 |
| judge.js | index.html の判定関数をそのまま呼ぶ CLI。ジョブが使う |
| 台帳 | `data/ledger.json`。購入・払戻と予算ガードの元 |
| サンプル | `data/samples/*.json`。結果付きの1レース1レコード。バックテストの材料 |
| アドendum | 変更の目的・範囲・禁止事項・検証を書いた設計文書。コード変更の前提 |
| 推定人気（推:） | SmartRc 由来の値。ツールが計算するものではない |
| 🛑／🚫／⚠️ | 総合判定の見送り記号。買わない |
| PR | GitHub の Pull Request。変更を main に入れる前の確認画面 |
