# docs/jobs — 定時／合図起動ジョブの手順書（自己完結）

各ジョブは Claude（Cowork スケジュールタスク）が**毎回新規セッション**で実行する。会話の記憶は無いので、
必要な文脈は本ディレクトリと `docs/`、プロジェクト知識、リポジトリだけから読む。

| ジョブ | 起動 | 手順書 | 役割 |
|:--|:--|:--|:--|
| J1 | 木 21:00 JST（定時） | `J1_race_selection.md` | 週末の候補レース選定（出典URL必須） |
| J2 | 土・日 07:30 JST（定時） | `J2_judge_and_bets.md` | スクショ→全頭JSON→`judge.js`→判定・買い目メモ |
| J3 | 人の合図で起動 | `J3_record_results.md` | 結果記録→`data/samples/`・`data/ledger.json` 更新→バックテスト |

## 共通セットアップ（各ジョブの冒頭で必ず行う）

```bash
git clone https://github.com/iamshojikenchiku-rgb/smart-yosou.git && cd smart-yosou
test -f scripts/judge.js || { echo "judge.js が main に無い（feature/g-layer-pi 未マージ）"; exit 1; }
npm install --no-audit --no-fund
npm run check            # 合格しなければ以後の判定はしない
```

## 共通ルール（運用フロー定義書 §5 の再掲・ジョブ版）

1. **ツール判定は絶対**。買い目は `scripts/judge.js` の出力以外から作らない。Claudeの所見は「所見」欄に分けて書く。
2. **🛑 / 🚫 / ⚠️ が出たら見送り**。買い目欄は「参考表示」と明記し、購入を促す文言を書かない。
3. **日程・レース名・出走表は必ずWeb検索で確認し、出典URLを成果物に残す**。確認できない情報は「未確認」と書く。
4. **確定着順・確定馬場・払戻は推測しない**。結果スクショに無い値は空欄のまま。
5. **推測で埋めない**。スクショ不足・JSON不整合・スクリプト失敗のときは買い目を出さず「入力待ち／要確認」で終了する。
6. **判定ロジック・閾値・スキーマは変更しない**（CLAUDE.md）。気づきは `docs/` への提案メモに留める。
7. 成果物はプロジェクト知識 `claude/weekly/` に書く（ファイル名は各手順書のとおり）。同名があれば上書きではなく末尾に「更新」節を追記する。
8. リポジトリへの push が拒否された場合（認可外）は、変更内容をプロジェクト知識 `claude/pending/` に保存し、成果物に「要取り込み」と書く。

## スクショのファイル名規約（人が投入するとき）

`YYYYMMDD_<レース名>_<種別>_<連番>.png`
- 種別: `出馬表` / `血統` / `推定人気` / `オッズ` / `結果`
- 例: `20260912_京成杯AH_出馬表_1.png`, `20260912_京成杯AH_推定人気_1.png`, `20260912_京成杯AH_結果_1.png`
- J2 は対象日の `YYYYMMDD_` で始まるファイルだけを読む。規約外のファイルは無視する。
