## 1. モジュール1の検証項目「追記レース名で荒れスコアが変化」について

### 現状（変更前 0da1226 時点）
- `ARERU_RACES` はすでに設計書の9レース全てを含む（＋七夕賞・函館記念）。
- 一覧は Step1 画面の「参考：荒れやすい主要レース」として**表示のみ**に使われている。
- 荒れスコア（`calcArereScore` ⑨）は `race.isAreru` チェックボックス（手動）でのみ +8 される。
  レース名との自動照合は存在しない。

### 決定（2026-09-05・ユーザー確認済み）
- **データ拡張のみ**を実施する（区分 `type`・備考 `note`・`source`・4月の `caution: true`）。
- レース名一致で `isAreru` を自動ONにする実装は、荒れスコアのロジック変更（禁止事項）に当たるため**行わない**。
- 検証項目は「追記した区分・備考が一覧表示に反映されること」に読み替える。
- 4月の `caution` 行は `name: "クラシック路線（桜花賞・皐月賞）"` として1行追加し、荒れスコアには一切関与させない。
- 既存名「阪神カップ」を優先し、設計書の「阪神C」は備考のみ補完（設計書「既存を優先」に従う）。

### 提案（未採用・次アドendumで検討）
- レース名入力欄と `ARERU_RACES` を照合し、「荒れやすいレースに該当します」の**注意表示だけ**を出す
  （チェックボックスは自動ONしない）。表示のみなら禁止事項に触れない。

## 2. 外部CDN参照（check.js 要件3）について

### 現状
- 変更前の `index.html` には `<script src="https://cdn.tailwindcss.com">` と Google Fonts の `<link>` が残っている
  （React/ReactDOM はインライン済み）。CLAUDE.md「外部CDN参照はゼロを維持」と食い違う。
- jsdom（外部リソース非読込）でも `#root` は描画されるため、Tailwind CDN が落ちても黒画面にはならず**装飾だけ失われる**状態。

### 決定（2026-09-05・ユーザー確認済み）
- `scripts/check.js` は上記の既存参照を「既知の例外」として**警告表示**に留め、
  それ以外の外部 script/link 参照が増えた場合のみ失敗させる。
- `npm run check -- --strict` で例外なしの厳格モードを用意した（Tailwind インライン化後に既定へ切替予定）。
- Tailwind のインライン化は本アドendumの範囲外のため**今回は行わない**。

### 提案（未採用）
- 別ブランチで Tailwind をビルド済みCSSとしてインライン化し、Google Fonts をシステムフォントへ代替する。
  完了後 check.js の `KNOWN_EXTERNAL` を空にして厳格モードを既定にする。

## 4. モジュール2の実装メモ（2026-09-05）

- 「馬別テーブルに列を3つ追加」は、現行UIがテーブルではなく**カード式ランキング**のため、各カード内に
  `π 3着内:xx.x% 公平複勝:x.xx倍 複勝:x.x倍 / π判定` の1行として追加した。既存の行・並び順・色分けは不変。
- グレーアウトは設計書の「🛑時」に加え、鉄則に列挙された **🚫・⚠️ でも同様に**適用した（総合判定ラベルの絵文字で判定。判定ロジック側は不変）。
- `odds_fuku` は `emptyHorse` / 取込 / 入力フォーム（複勝オッズ下限・任意）に追加。エクスポートは既存の `horses` をそのまま出すため自動で含まれる（17キー目・任意）。
- 条件Aを満たし `odds_fuku` が無い馬は「率のみ（複勝未入力）」と表示（設計書の判定保留 "—" を複勝欄で表現）。
- 定数 `PI_LAYER_K = 0.5` は `calcG_PiReference` 直前の1箇所のみ。較正後はここだけ差し替える。
- テスト: `npm run test:g`（scripts/test-g-layer.js・jsdom で取込→描画を実走）。

## 5. モジュール3の実装メモ（2026-09-05）

- 「結果入力」は**既存の結果入力モーダル**（保存済みレース → 結果：1〜3着・払戻・購入額）を流用し、
  `date`（開催日）と `final_baba`（確定馬場）の2欄を追加した。既存の `result` 構造は保持（旧形式の保存データも開ける）。
- エクスポートは「保存済みレース」画面上部の「JSONをコピー」。1〜3着が入力済みの保存レースを配列で出力
  （クリップボード不可時はテキストエリアに表示）。1レース1オブジェクト＝ `buildBacktestRecord(saved)`。
  各層スコアは保存時の `race/horses` から**再計算**して出す（保存時に判定結果を凍結していないため）。
- 出力キーは §3.1 の例に加え、`judgement`（荒れスコア・軸信頼度・総合判定）、`blood_total`（S_i）、`pi_p/pi_fair/pi_judge`、`in3` を含む。
- 集計は `scripts/backtest.js`（依存なし）。`npm run backtest`。指標1〜4と §3.3 の採用基準判定を出す。
  - 複勝回収率は **複勝オッズ下限×100円** の保守値（実払戻より低め）。
  - k 走査は 0.2〜1.0（0.05刻み）。基準線として k=0（血統不使用＝全頭 3/n）の対数損失も併記。
- **遡及サンプルについて**：設計文書に結果と血統の事実が文書化されているのは オークス（5/24）と しらさぎS（6/21）の2件のみで、
  全頭の入力JSON・各層スコア・複勝オッズは文書に無い。よって `partial: true` として事実のみ収録し、集計対象外とした。
  日本ダービー・安田記念・宝塚記念は文書化データが無く**作成していない**（推測禁止）。「過去5レース遡及入力」は未達。
  当時の入力JSONが手元にあればツールで読込→結果入力→エクスポートで完全版にできる。
- 「集計が走ること」の確認は、ツール自身の `buildBacktestRecord` で生成した**合成データ**（`synthetic: true`・既定では除外・`--include-synthetic` で集計）と、
  `npm run test:bt`（jsdom で 保存→結果入力→エクスポート→backtest.js を実走）で行った。

## 6. 段階A（週末推奨買い目システム）の実装メモ（2026-09-05）

- `scripts/judge.js`：index.html を jsdom で読み、判定関数を**そのまま**呼ぶCLI。入力整形は取込（importData）と同じ既定値。
  `scripts/test-judge.js` で、同じJSONをブラウザ取込した画面テキストと 荒れスコア／軸信頼度／総合判定／買い目の式と金額／合計／過剰人気／π行 が一致することを固定。
- `decision` は総合判定ラベルの 🛑/🚫/⚠️ で機械的に決める（運用フロー §2 ステップ5）。判定ロジックには触れていない。
- 予算ガード：`data/ledger.json`（月10,000／週2,500／勝負所3,000）。週は月曜始まり。超過時は `decision = 予算超過のため見送り`。
- 手順書：`docs/jobs/README.md`・`J1_race_selection.md`・`J2_judge_and_bets.md`・`J3_record_results.md`。新規セッションが読むだけで実行できる自己完結の書き方にした。
- **観察（設計書にない事項・変更していない）**：`judgeQuadrant` の助言文と `buildBets` の配分が一致しないケースがある。
  例：荒れスコア≥65 × 軸信頼度「中」→ 総合判定は「💎 お試し（ワイドBOX4頭で500円）」だが、`buildBets` は「買い場（ワイド1頭軸流し1,000円＋3連単500円＝1,500円）」を返す。
  どちらが正か（助言文か買い目か）は設計判断のため、次アドendumで決める。judge.js は現状どおり `buildBets` の出力を出し、助言文も併記している。
