## 1. 目的

1. 毎週の入力（出馬表・血統・オッズ）を JRA-VAN から自動で作り、スクショ投入を不要にする
2. 過去5年分のレースで現行ロジックのバックテストを行い、**ロジックに優位性があるかを数値で判断する**

## 2. 変えないもの（CLAUDE.md・構成案 P3/P4 の再確認）

- 荒れスコア・軸信頼度・🛑/🚫/⚠️の閾値・予算ティア・買い目ロジック・単一ファイル構造
- 判定は `index.html` の関数を `scripts/judge.js` 経由で呼ぶだけ。ロジックの複製・再実装は禁止
- 16キースキーマ。追加は任意キーのみ（本書では `est_pop_source` を1つ追加。§6）
- G層πは表示のみ（基準達成まで）
- 月予算10,000円・原則1〜2レース

本書で変わるのは**入力の作り方（取得元）**と**移行条件**だけ。

## 3. 段階B移行条件の改訂（構成案 §5 を置き換え）

旧: samples 10レース以上 → 推定人気の代替をバックテストで比較 → 自動取得を設計
新:
1. JRA-VAN の過去データから、現行ロジックへの入力JSON（16キー）を再構成できること（§5）
2. 推定人気の代替候補を §7 の手順で比較し、1つを選定できること
3. 選定した代替で、検証期間（ホールドアウト）の成績が §8 の基準を満たすこと

## 4. 構成

```
[Windows PC]
  JV-Link（JRA-VAN公式・32bit COM）
     │  32bit Python + pywin32
     ▼
  keiba-data（非公開）
   ├─ raw/        JV-Data の取得ファイル（再配布しない）
   ├─ db.sqlite   レース・出走・成績・払戻・血統・オッズ
   └─ export/     judge.js 入力JSON（16キー＋任意キー）
     │
     ├─▶ 過去分: バックテスト（judge.js をローカルで一括実行）
     └─▶ 毎週分: 金夜〜土朝に該当レースのJSONを出力 → プロジェクトへ投入
                                                  │
[クラウド]                                         ▼
  J2（土日07:30）: スクショの代わりに export JSON を読む → judge.js → 買い目メモ（従来どおり）
```

- keiba-data は**PC内または非公開リポジトリ**に置く。smart-yosou は Pages 公開のため Public のまま（OPERATION_MANUAL §7）で、生データ・全頭の派生データは置かない
- J2 の入力切替は、スクショ方式を残したまま「export JSON があればそれを優先」とする（後方互換。J2 手順書の改訂は本書の実装後）

## 6. 推定人気（est_pop）の代替

前提: `pop_tan`（単勝人気）とは**別の指標**でなければならない。est_pop と pop_tan の差（過剰人気・ねじれの検出）を使う箇所があるため、pop_tan をそのまま入れると判定の意味が変わる（実装時に参照箇所を確認して記録）。

確認結果（2026-10-12）: 参照箇所は判定に効くもの6件・表示等3件（`docs/memo/2026-10-12_16key_definition.md` §3）。est_pop に pop_tan と同じ値を入れると、乖離による加減点が0、過剰人気が常に0頭となり、勝負所条件③が成立しなくなるため ⚡勝負所が出なくなる。

候補（バックテストで比較）
| 記号 | 指標 | 考え方 |
|:--|:--|:--|
| S1 | 前日発売の単勝オッズ順位 | 当日の人気が固まる前の評価。データの有無を JRA-VAN で要確認 |
| S2 | 前走の単勝人気（同条件補正なし） | 単純・欠損が少ない |
| S3 | 簡易推定（前走着順・クラス・騎手リーディング順位の合成） | SmartRc の推定人気に近い発想。重みは S3 内の固定値とし、判定ロジックには触れない |

- 任意キー `est_pop_source` を追加（値: `"smartrc"` / `"S1"` / `"S2"` / `"S3"`）。判定には使わず、記録と比較のためだけに持つ
- 選定は §7 の選定期間で行い、検証期間の成績で確認する

## 7. バックテスト計画

| 項目 | 内容 |
|:--|:--|
| 期間 | 2021〜2025年。**選定期間 2021〜2023**（代替指標の選定）／**検証期間 2024〜2025**（結論用・選定に使わない） |
| 対象レース | J1 の選定規則を機械化した集合: ARERU_RACES 該当／ハンデ重賞／小回りの重賞・OP。週1〜2レースに絞る規則も再現 |
| 予算 | 月10,000円・週2,500円（勝負所3,000円）の予算ティアをそのまま適用 |
| 実行 | export JSON → `scripts/judge.js` 一括実行 → 実際の払戻と突合 |
| 出力 | 回収率・的中率・見送り率・最大連敗・月別収支・判定区分別（🛑🚫⚠️で見送った週の「見送り正解率」も） |
| 記録 | 結果の集計のみを `docs/` に残す。全頭データは keiba-data 側に置く |

禁止事項: 検証期間の結果を見てから代替指標や対象レース規則を変えること（過学習）。変えたい場合は新しいアドendumを書き、別の検証期間を用意する。

## 8. 継続判定（無料体験の終了前に判断）

| 検証期間の回収率 | 判断 |
|:--|:--|
| 100%以上 | JRA-VAN 継続。J2 を export JSON 方式に切り替えて本運用 |
| 80〜100% | 継続は「改善案のアドendumを書く」ことが条件。改善の見込みが無ければ解約 |
| 80%未満 | 解約。現行ロジックでの馬券購入も見直す（予算の停止を含めて人が判断） |

補足: 回収率だけでなく、見送り率が極端（例: 9割以上見送り）でないか、月別の偏りが大きくないかも併記する。
